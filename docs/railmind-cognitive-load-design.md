## 1. 問題

原本的設計文件把 RailMind 定位成「思維流日記」：三種關係（`parent_id`、`thread_id`、`tag_id`）、可按標籤／日期／思維線回顧。但實際使用一個月後，介面長成 6 個一級入口、每條記錄 10 個以上動作、3 個「回到今天」、2 種瀏覽模式，使用者在記錄前要先決定「要不要續寫／引用／關聯」，認知負擔超過記錄本身的價值。

這次要回答的問題不是「砍功能」，而是：**哪些概念是產品設計帶來的，哪些是使用者真正長出來的。**

## 3. 低使用率的三種判讀

使用率量的是「操作成本」，不是「價值」。同一個低數字可能來自三種原因，必須分開處理：

| 維度 | 判讀 | 處置 |
|---|---|---|
| 思維線 | 專案維度真實存在（57 條有主題、88% 沒掛），但掛接要開 modal、搜尋、決定 | 合併進抽屜、一鍵掛，**不降級** |
| 標籤 | 評價詞彙（跟風／認真規劃／情緒化）只在第一週使用，之後 0 | 退出預設，資料保留 |
| 抽屜 | 9/23 才出現，19 個在 3 天內建立 | 剛開始，升為主角 |
| 艾森豪／價值 | 概念重疊、用量極低 | 移入回顧分頁 |
| 引用 | 語意其實是「回覆／確認」 | 保留在 ⋯ |

結論：**思維線與標籤的低使用率，一半是設計造成的（成本太高），一半是內容不支持（評價式標籤沒有延續）。** 不能只用數字判死刑。

## 4. 三個獨立視角

| 視角 | 定位 | 關鍵主張 |
|---|---|---|
| 設計參考（Things／Workflowy／Bullet Journal） | 每條記錄都是可執行的碎片 | 借大綱的形狀、下一步焦點、低儀式狀態；不借分類系統、每日遷移、雙向連結語法 |
| 架構（心智模型收斂） | 多專案並行時的外接工作記憶 | 收斂成兩個名詞：想法＋專案；思維線必須併入，不是降級 |
| 獨立評審 | 承諾收束器 | 碎片先暫存，只把少數升級為承諾並確保勾掉；真正的斷點是碎片與承諾混流 |

三者一致的地方：合併容器、收斂動作、清單化子步驟、矩陣退出預設、不加新的分類層。

分歧與裁決：

1. **標籤要不要併進抽屜？** 獨立評審主張合一；裁決為**不併**。標籤是跨專案的屬性（情緒化／跟風），併進容器會失去意義，且資料早已停用。
2. **要不要留一個矩陣在記錄列？** 架構視角建議留價值象限；裁決為**都移回顧**，8 條用量撐不起常駐按鈕。
3. **要不要在捕捉時分「暫存／承諾」？** 不新增欄位、不在最高頻動作加決定；改成唯讀的「未收束」視圖。

## 5. 唯一模型

```
抽屜（專案）
 └ 念頭（一行文字 + 時間）
     ├ 子念頭（縮排，可再縮排）
     └ ☑ 勾消（狀態，不是另一個東西）
```

| 名詞 | 對應欄位 |
|---|---|
| 抽屜 | `deskRows / drawers`；`thread_id` 併入 |
| 念頭 | `records`；`parent_id` 是縮排關係 |
| 勾消 | `is_completed` |

標籤、四象限、價值、引用、底色、圖片、錄音都是念頭的可選屬性，不進預設介面。

### 定位

**這不是第二大腦，而是同時跑多個專案時的外接工作記憶。**

它與其他產品的差異：

| 能力 | 別人也有 | 這裡多出來的 |
|---|---|---|
| 一行捕捉 | Drafts／Apple Notes | 時間戳與跨日時間流 |
| 分支即子步驟 | Workflowy／Logseq | 節點有時間與完成狀態 |
| 抽屜即專案 | Things | 19 個抽屜是使用者自己長出來的 |
| 勾消即收束 | Todoist／子彈筆記 | 完成項仍留在時間流，看得到脈絡 |

簡化不是把它變成 Todoist，而是把它已經長出來的形狀磨順。

## 6. 設計決策

### 6.1 專案是唯一容器

- 思維線併入抽屜，不再是一級入口；13 條舊思維線出現在專案頁的「舊思維線」區，可逐條併入同名抽屜。
- 抽屜升為一級入口。
- 不改資料：`thread_id` 保留。

### 6.2 一級入口 6 → 3

`記錄`、`回顧`、`專案`。四象限與價值象限成為回顧頁的分頁；標籤退到次要區塊。

### 6.3 單條念頭只露三個動作

```
⎇ 續寫   ✓ 勾消   ⋯ 更多
```

`⋯` 內是分類與編輯（專案、標籤、回覆、優先級、編輯附件與外觀、刪除）。有子節點的父念頭不顯示勾選框，只顯示子樹進度；群組完成／取消完成收在 `⋯` 裡。

### 6.4 子步驟清單化

- 父節點有 ≥2 個子節點時，子節點渲染成可勾選清單。
- 父節點只顯示標題與 `2/6` 進度，不同時塞多種狀態。
- 資料支援任意深度；介面只展開兩層，第 3 層起收合成 `▸ N 步`。
- 子節點跨日時顯示日期徽章。
- 不做每日遷移，避免罪惡感。

### 6.5 未收束（唯讀視圖）

定義：**已歸屬專案、或本身有子步驟的念頭，且尚未勾消。** 純葉端子步驟不單獨列出，否則 100 多條碎片會再次淹沒真正的承諾。

### 6.6 標籤退出預設，但不併入抽屜

標籤是跨專案屬性；資料保留，只從常駐介面移入 `⋯`。

### 6.7 兩個矩陣移入回顧

四象限與價值象限不再出現在記錄列或一級導航。

### 6.8 重複入口收斂

- 標題列與提示條的「回到今天」移除，只留浮動按鈕。
- 模式列不常駐，記住上次選擇。
- 日期導航收成一個膠囊。

## 13. 時間與時區

- 持久化時間一律是 UTC ISO（`created_at` / `updated_at`），這是唯一的絕對時間。
- 所有顯示、日期分組與「今天」固定使用 **東八區（Asia/Shanghai，UTC+8）**，不再使用瀏覽器所在時區。
- `dateUtils` 是唯一的轉換入口；不要再直接呼叫 `date-fns` 的本地時區格式化，也不要用 `getFullYear()`／`getMonth()` 等本地 getter。
- 週報／匯出的 `timezone` 欄位固定為 `Asia/Shanghai`。
- 若之後要支援旅行時的「當地日」，再額外儲存建立當下的 `local_date`／`tz`，不要改回瀏覽器時區。
